## §1 スコープと前提

### 対象
本プロジェクトの **現実装** (Spresense + GS2200M / PC viewer / TCP/8888 平文 MJPEG) を対象。

### 想定環境
- **本来想定**: 同一 LAN 内 (家庭 / 小規模事務所) で運用 (要求書 v1.0 Q24)
- **WiFi**: WPA2-PSK で暗号化 (`wifi_manager.c:152`)
- **物理境界**: Spresense + AP + PC が同一物理空間に存在

### スコープ外
- 公開インターネット経由のアクセス (本プロジェクト想定外、要求書 v1.0 Q24)
- WiFi 暗号化突破 (WPA2 のセキュリティは本書の対象外、AP 側の責務)
- Spresense ファームウェア改竄 (物理アクセスを伴う高難度攻撃)

## §3 信頼境界 (Trust Boundaries)

```
┌──────────────────────────────────────────────────┐
│ Trust Boundary: 物理 LAN (信頼)                   │
│                                                    │
│  [Spresense] ─SPI─ [GS2200M] ─WiFi─ [AP] ─WiFi─ [PC viewer]
│       │                                              │
│       └──USB CDC-ACM──────────────────────────────┘
│                                                    │
│ ※ WPA2-PSK で暗号化                              │
└──────────────────────────────────────────────────┘
                            │
                            │ Trust Boundary を越える攻撃
                            │ (WPA2 突破 or LAN 物理侵入)
                            ▼
                       ┌──────────┐
                       │ Adversary │
                       │ (LAN 内)  │
                       └──────────┘
```

**重要な前提**: WPA2 認証を突破され LAN 内に入った攻撃者は **完全に内部信頼境界内**となり、本プロジェクトの実装上の防御は **ほぼ無効**。

## §4 採点基準 (DREAD)

| 指標 | 1-3 (低) | 4-6 (中) | 7-10 (高) |
|---|---|---|---|
| **D**amage potential (影響度) | 軽微 (情報漏洩のみ) | 中程度 (運用影響) | 重大 (映像漏洩 + システム停止) |
| **R**eproducibility (再現性) | 特殊条件必須 | 一定条件で再現 | 任意の時に再現可 |
| **E**xploitability (攻撃容易性) | 高度な技術必要 | 標準的なツールで可 | スクリプト一発 |
| **A**ffected users (影響範囲) | 単一セッション | 単一デバイス | 全システム + 履歴データ |
| **D**iscoverability (発見容易性) | 難 (ソース解析必要) | 中 (一般的な調査) | 易 (ポートスキャン等で即発見) |

**DREAD スコア = D+R+E+A+D の合計 (max 50)**

**閾値**:
- 🔴 ≥ 35: 緊急対策推奨
- 🟡 25-34: 計画的対応
- 🟢 < 25: 監視継続

## §5 STRIDE × DREAD 脅威シナリオ (16 件)

### S — Spoofing (なりすまし)

#### TS-1: PC viewer になりすまし

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が任意の TCP クライアントとして port 8888 に接続、正規 viewer のフリして映像受信 |
| **D** | 8 (映像漏洩 + 運用阻害) |
| **R** | 10 (常時再現可) |
| **E** | 9 (`nc spresense_ip 8888` で完了) |
| **A** | 9 (システム全体の映像) |
| **D** | 10 (ポートスキャンで発見容易) |
| **DREAD 計** | **46** 🔴 |
| **現対策** | ❌ 認証なし (誰でも接続可) |
| **軽減策** | TLS-PSK or アプリ層認証 (Phase 12 セキュリティ判断 Option B) |

#### TS-2: Spresense デバイスになりすまし (悪意 AP)

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が同一 SSID/Pass の偽 AP を立て、Spresense を誘導 (Evil Twin) |
| **D** | 7 (システム機能停止) |
| **R** | 5 (場所と機材必要) |
| **E** | 5 (rogue AP ツール使用) |
| **A** | 8 (Spresense 全体) |
| **D** | 5 (検知困難、Spresense は AP 識別子検証なし) |
| **DREAD 計** | **30** 🟡 |
| **現対策** | ❌ AP MAC 固定なし、AP 識別検証なし |
| **軽減策** | AP MAC アドレス固定設定 (低コスト) |

### T — Tampering (改ざん)

#### TT-1: MJPEG パケット改ざん (中間者攻撃)

| 項目 | 内容 |
|---|---|
| **脅威** | LAN 内攻撃者が ARP spoofing → 中間者 → MJPEG 改竄 → 偽映像挿入 |
| **D** | 9 (偽映像で運用判断ミス) |
| **R** | 5 (ARP poisoning 必要) |
| **E** | 5 (Ettercap 等で可能だが多段階) |
| **A** | 9 (全映像) |
| **D** | 4 (検知困難、CRC は再計算可能) |
| **DREAD 計** | **32** 🟡 |
| **現対策** | 🟡 CRC-16-CCITT のみ (改ざん耐性なし、再計算可能) |
| **軽減策** | HMAC-SHA256 or TLS による完全性保護 |

#### TT-2: 録画ファイル MP4 改ざん (PC 側)

| 項目 | 内容 |
|---|---|
| **脅威** | PC ローカル攻撃者が MP4 ファイルを編集、証拠改竄 |
| **D** | 9 (証拠としての MP4 信頼性失墜) |
| **R** | 10 (FS 直接編集) |
| **E** | 7 (動画編集ツールで可能) |
| **A** | 5 (PC 側のみ) |
| **D** | 3 (改ざん痕跡を消すには高度な技術) |
| **DREAD 計** | **34** 🟡 |
| **現対策** | ❌ ファイル署名・検証なし |
| **軽減策** | 録画ファイルのハッシュチェーン記録 (Phase 13+) |

### R — Repudiation (否認)

#### TR-1: 運用者がアクション否認 (録画停止等)

| 項目 | 内容 |
|---|---|
| **脅威** | 「録画停止操作はしていない」と主張、ログがなく検証不可 |
| **D** | 4 (運用上の責任問題) |
| **R** | 8 (操作記録なしのため繰り返し可) |
| **E** | 10 (操作するだけ) |
| **A** | 3 (個別事案) |
| **D** | 8 (操作ログがないため発見困難) |
| **DREAD 計** | **33** 🟡 |
| **現対策** | ❌ 操作ログなし、syslog にも記録されない |
| **軽減策** | GUI 操作の監査ログ + 署名 (Phase 13+) |

#### TR-2: Spresense 側障害発生時の否認

| 項目 | 内容 |
|---|---|
| **脅威** | 「障害は発生していない」と主張、metrics packet が存在しない期間の証拠なし |
| **D** | 5 (運用責任の所在不明) |
| **R** | 7 (再起動で metrics リセット) |
| **E** | 9 (シリアルログ確認のみ、syslog は揮発) |
| **A** | 5 (個別事案) |
| **D** | 7 (ログ署名なし) |
| **DREAD 計** | **33** 🟡 |
| **現対策** | 🟡 metrics packet で稼働中の状態は記録、ただし永続化なし |
| **軽減策** | 永続ログ (SD カード) + 署名 (Phase 13+, X-5 関連) |

### I — Information disclosure (情報漏洩)

#### TI-1: MJPEG 盗聴 (Wireshark)

| 項目 | 内容 |
|---|---|
| **脅威** | LAN 内攻撃者が Wireshark で TCP/8888 のパケットキャプチャ → MJPEG 復元 |
| **D** | 10 (全映像漏洩) |
| **R** | 10 (常時) |
| **E** | 9 (Wireshark + 簡易スクリプト) |
| **A** | 9 (全期間の映像) |
| **D** | 10 (ポート発見容易) |
| **DREAD 計** | **48** 🔴 |
| **現対策** | ❌ 平文送信、暗号化なし |
| **軽減策** | TLS 1.3 + AES-256-GCM (構造的天井 #4 RAM 制約で困難)、Tier 2/3 移行と同時に |

#### TI-2: WiFi 認証情報のリポジトリ漏洩

| 項目 | 内容 |
|---|---|
| **脅威** | `wifi_config.h:17-18` がリポジトリに track され、公開時に SSID/Pass 漏洩 |
| **D** | 8 (LAN 侵入経路提供 → TS-1, TI-1 等の起点) |
| **R** | 10 (リポジトリ閲覧で常時可能) |
| **E** | 10 (git clone のみ) |
| **A** | 9 (LAN 全体への侵入経路) |
| **D** | 8 (公開リポジトリなら検索でヒット) |
| **DREAD 計** | **45** 🔴 |
| **現対策** | ❌ git track 中、`.gitignore` 化されていない (X-7 で対応予定) |
| **軽減策** | X-7 (緊急度高): wifi_config.h.example + .gitignore |

#### TI-3: metrics packet 経由の運用情報漏洩

| 項目 | 内容 |
|---|---|
| **脅威** | metrics packet (sync_word `0xCAFEBEEF`) を盗聴し、運用パターン (FPS / 切断頻度 / 錯誤数) を分析 |
| **D** | 4 (運用情報のみ、映像本体は別) |
| **R** | 10 (常時) |
| **E** | 7 (Wireshark + parser) |
| **A** | 5 (運用情報のみ) |
| **D** | 6 (sync_word が公開されている前提) |
| **DREAD 計** | **32** 🟡 |
| **現対策** | ❌ 平文 |
| **軽減策** | TI-1 と同じ TLS で覆い隠す |

### D — Denial of Service

#### TD-1: TCP 8888 への接続スパム (DoS)

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が大量の TCP 接続を試行、Spresense リソース枯渇 |
| **D** | 7 (サービス停止) |
| **R** | 10 (常時) |
| **E** | 8 (簡易スクリプト) |
| **A** | 9 (全 viewer 影響) |
| **D** | 8 (ポート発見容易) |
| **DREAD 計** | **42** 🔴 |
| **現対策** | ❌ rate limit なし、TCP_SERVER_BACKLOG=1 で 1 接続のみ受け付け (副作用的緩和) |
| **軽減策** | accept rate limit + IP allowlist (低コスト) |

#### TD-2: 大量 MJPEG リクエストでバッファ枯渇 (構造的天井 #1)

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が PC viewer なりすましで接続後、受信を遅らせて GS2200M tx_buff 枯渇を誘発 |
| **D** | 7 (システム劣化) |
| **R** | 8 (slow client 実装可能) |
| **E** | 6 (TCP slow read 攻撃の知識必要) |
| **A** | 8 (システム全体) |
| **D** | 6 (検知困難、正常な客と区別不能) |
| **DREAD 計** | **35** 🔴 |
| **現対策** | 🟡 TCP Health Monitor で検知、ただし対処は無効な再接続のみ |
| **軽減策** | client send rate 監視 + 切断、TS-1 と組み合わせて TLS-PSK 認証必須化 |

#### TD-3: WiFi 妨害電波 (Jamming)

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が 2.4 GHz 帯の妨害電波で WiFi 通信を遮断 |
| **D** | 6 (サービス停止) |
| **R** | 8 (機材があれば常時) |
| **E** | 4 (jammer 機材 + 法的リスク) |
| **A** | 8 (全 WiFi 通信) |
| **D** | 6 (RSSI 低下で間接検知可能) |
| **DREAD 計** | **32** 🟡 |
| **現対策** | ❌ ハード経由のみ (USB CDC-ACM Tier C 切替) |
| **軽減策** | Tier C 自動フォールバック (Phase 12+) |

### E — Elevation of privilege (権限昇格)

#### TE-1: PC viewer プロセスの権限昇格

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が PC viewer のプロセスメモリに侵入、root 権限取得試行 |
| **D** | 9 (PC 全体) |
| **R** | 3 (脆弱性発見必要) |
| **E** | 4 (Rust メモリ安全で困難) |
| **A** | 9 (PC 全体) |
| **D** | 5 (一般的なエクスプロイト調査) |
| **DREAD 計** | **30** 🟡 |
| **現対策** | 🟢 Rust メモリ安全性 + bounded(3) で buffer overflow 防御 |
| **軽減策** | OS 側のサンドボックス (systemd, AppArmor 等) |

#### TE-2: Spresense デバイスの root 化

| 項目 | 内容 |
|---|---|
| **脅威** | 攻撃者が SPI bus 物理アクセスでファームウェア書換 |
| **D** | 10 (デバイス完全乗っ取り) |
| **R** | 2 (物理アクセス必須) |
| **E** | 2 (組込み解析の専門知識) |
| **A** | 7 (個別デバイス) |
| **D** | 3 (検知困難) |
| **DREAD 計** | **24** 🟢 |
| **現対策** | 🟢 物理境界が前提、CXD5602 secure boot は未活用 |
| **軽減策** | 物理セキュリティ (筐体施錠) — Phase 13+ で再評価 |

## §9 観察と方針

### 観察 1: 「LAN 内攻撃者」が最大の脅威源
WPA2 突破後 LAN 内に入った攻撃者は、本実装の**全防御を無効化**できる (DREAD 45+ が複数)。
→ **WPA2 強度 + 物理 LAN 隔離**が現状の主要防御。これを運用文書で明示する必要 (X-4)。

### 観察 2: 認証なしが I/S/D で連鎖的に脆弱
TS-1 (なりすまし) → TI-1 (盗聴) / TI-3 / TD-1/TD-2 (DoS) が同じ「認証なし」起点。
**TLS-PSK 1 機構の導入で複数脅威を一気に緩和できる** (費用対効果が高い)。

### 観察 3: Tampering (改ざん) と Repudiation (否認) は中位
DREAD 30-34 帯。緊急ではないが、防犯カメラとしての**証拠能力**を確保するなら長期で対応必要。

### 観察 4: Tier 2/3 移行が前提となる重い緩和策
TLS スタック搭載 (TI-1) は構造的天井 #4 (RAM 1.5MB) で困難。**Tier 2/3 移行と同時実施**が現実的。

### 観察 5: TI-2 (WiFi 認証情報) は緊急対応必須
DREAD 45、しかも **緩和策のコストが小さい** (X-7 で `.gitignore` + .example 化のみ)。Phase 12 序盤で必ず実施。
