# キューシステムの数学的モデルと制御理論分析

## 1. システム状態方程式

### 1.1 action_queue (第1段キューシステム)

**状態変数**: `q₁(t)` = キュー深度 [frames]
**入力**: `u₁(t)` = カメラフレーム生成率 [frames/s]
**出力**: `y₁(t)` = TCP処理フレーム率 [frames/s]

**状態方程式**:
```
dq₁(t)/dt = u₁(t) - y₁(t)
```

**制約条件**:
```
0 ≤ q₁(t) ≤ 7  (物理的制約)
u₁(t) = 30 [fps] (一定)
y₁(t) = f(q₁(t), τ₂)  (TCP処理能力に依存)
```

**平衡点解析**:
```
平衡状態: dq₁/dt = 0
⟹ u₁ = y₁
⟹ q₁* = f⁻¹(30, τ₂)

Phase 7.3.3: q₁* = 6-7 (飽和状態)
Phase 8-9.2: q₁* = 1-2 (安定状態)
```

### 1.2 TCP通信系の動的モデル

**伝達関数**:
```
G_tcp(s) = K₂ e^(-θs) / (τ₂s + 1)

ここで:
K₂ = 0.85 (実効ゲイン、ドロップ考慮)
τ₂ = 134ms (時定数)
θ = 10-50ms (可変遅延)
```

**周波数応答**:
```
|G_tcp(jω)| = K₂ / √((ωτ₂)² + 1)
∠G_tcp(jω) = -ωθ - arctan(ωτ₂)

帯域幅: ωBW = 1/τ₂ = 7.46 rad/s ≈ 1.19 Hz
```

### 1.3 健全性監視制御系

**移動平均フィルタ**:
```
h_avg(n) = (1/N) Σ(k=0 to N-1) h(n-k)
N = 10 (窓幅)
```

**スパイク検出アルゴリズム**:
```
spike(n) = {1, if h(n) > h_thresh
           {0, otherwise

h_thresh = 200ms
spike_total = Σ spike(n)
```

**予測制御**:
```
J = Σ(k=1 to N) [e(k|n)² + λΔu(k|n)²]
e(k|n) = h_ref - h(k|n)
h_ref = 134ms (目標値)
```

## 2. システム安定性解析

### 2.1 リアプノフ安定性

**action_queueの安定性条件**:
```
V(q₁) = q₁²/2  (リアプノフ関数候補)

dV/dt = q₁ × dq₁/dt = q₁(u₁ - y₁)

安定条件: dV/dt < 0 when q₁ ≠ 0
⟹ sign(q₁) × (u₁ - y₁) < 0
⟹ y₁ > u₁ when q₁ > 0
```

**Phase 8改善の数学的根拠**:
```
Phase 7.3.3: E[y₁] = 12.6 fps < u₁ = 30 fps ⟹ 不安定
Phase 8: E[y₁] = 22.3 fps ≈ u₁ = 30 fps ⟹ 準安定
```

### 2.2 周波数領域解析

**開ループ伝達関数**:
```
L(s) = G_controller(s) × G_plant(s)
     = G₁(s) × G₂(s) × G₃(s) × G₄(s) × G₅(s)
```

**安定余裕**:
```
ゲイン余裕: GM = 1/|L(jωgc)| where ∠L(jωgc) = -180°
位相余裕: PM = 180° + ∠L(jωpc) where |L(jωpc)| = 1
```

## 6. 最適化と性能限界

### 6.1 制約条件下の最適化問題

**目的関数**:
```
minimize: J = ∫₀^T [α(q₁(t) - q₁_ref)² + β(u₁(t) - u₁_ref)²] dt

subject to:
dq₁/dt = u₁(t) - y₁(t)
0 ≤ q₁(t) ≤ 7
0 ≤ u₁(t) ≤ 30
y₁(t) = f(network_state)
```

**パレート最適解**:
```
Phase 9.2 = パレート境界上の解

```

### 6.2 理論限界分析

**情報理論的制約**:
```

C = B × log₂(1 + SNR)

情報理論容量: C_max = 20 Mbps
```
