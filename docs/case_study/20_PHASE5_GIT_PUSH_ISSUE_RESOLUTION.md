## 📚 応用可能な汎用的知識

### **1. Git大容量管理のベストプラクティス**

**事前予防策:**
```bash
# ファイルサイズ監視
find . -size +50M -type f

# .gitignore設定
echo "*.pcap" >> .gitignore
echo "*.csv" >> .gitignore  # 測定データのみ
echo "docs/**/raw_data/" >> .gitignore

# Git LFS設定
git lfs track "*.pcap"
git lfs track "*.bin"
```

**事後対策:**
```bash
# 1. 段階的プッシュ
for commit in $(git log --reverse --pretty=format:"%h"); do
  git push origin $commit:main
done

# 2. Filter-branch
git filter-branch --index-filter \
  'git rm --cached --ignore-unmatch <large-file-pattern>' \
  origin/main..main

# 3. 代替: git filter-repo（推奨）
git filter-repo --invert-paths --path <large-file-pattern>
```

### **2. エラーパターン別対処法**

**HTTP 408 Request Timeout:**
```yaml
原因: ファイルサイズ・転送時間超過
対処: git config http.timeout 3600
      git config http.postBuffer 1048576000
      段階的プッシュ実行
```

**HTTP 500 Internal Server Error:**
```yaml
原因: サーバー処理制限・累積負荷
対処: 時間間隔を開けて再試行
      SSH接続への変更
      履歴書き換えによる軽量化
```

**Connection Reset / Network Error:**
```yaml
原因: ネットワーク不安定性
対処: git config http.lowSpeedLimit 0
      git config http.lowSpeedTime 999999
      接続方式変更（HTTPS → SSH）
```
